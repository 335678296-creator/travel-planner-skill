# 协作看板格式规范（老板偏好，行程类）

核心原则：**全表格、不要长卡片；一眼看清"去哪、怎么去、花多久、办没办"。**

⚠️ "全表格"≠"一大堵墙"。超过 7 天的行程直接堆 15 张表，老板会喊"字太多看着乱"（实战翻车过一次）。**天数多时必须先做版面分层**：

## 版面分层（>7 天行程必做）

- **Hero 横幅**：深色渐变头图区，标题 + 路线一句话 + 统计 chips（X天X晚 · X家酒店 · X段航班 · X件急订），让老板 3 秒抓到全局
- **吸顶导航条**：`position:sticky` 顶部，放 总表/待办/D1-D13 跳转锚点（`html{scroll-behavior:smooth;scroll-padding-top:64px}`）
- **每天一张卡片**：表格外包 `.day` 圆角卡片，卡头彩色横条写 `D几 + 日期 + 当日主题`；**按段落/国家给卡头上不同色**（如冰岛蓝、特罗姆瑟紫、奥斯陆绿），扫颜色就知道在哪一段
- **餐厅行**：米色底 + 金色左边条（`tr.food`），🍽 一眼可辨
- **状态徽章只保留 4 色**：✅绿 / ⏳黄 / ⬜红 / 🆓灰
- **预订原则压成 🔴🟡🟢 三行优先级**，不要写大段文字
- 图片懒加载用 JS 加（`img.loading='lazy'`），不要改表格 HTML——表格 innerHTML 是同步快照，改动会导致旧云端状态错位

## 页面结构

1. **顶部：📒 总表**（所有可编辑内容必须放在 `<table>` 里，同步脚本按表格索引工作）
   - 列：`项目 | 日期 · 时间 | 状态 | 预约入口 / 备注`
   - 状态列用徽章 class：`st-ok`=✅ 已订、`st-todo`=⬜ 未订、`st-wait`=⏳ 待定、`st-free`=免费/无需办
   - 待办事项把**预约网址做成可点链接**、电话、确认号留白 `______` 让执行人填
   - 表上方放一行预订原则/注意事项（如"能提前 1 天订的不要提前订"及例外清单）
2. **每天一张表**（行程类）：`时间 | 去哪 | 怎么去 | 花多久 | 状态`
   - "去哪"单元格：小图 + 中文名（英文小注）+ 一句话"是什么" + 停留时长 + `📍 地图` 链接
   - 地图链接格式：`https://www.google.com/maps/search/?api=1&query=<地名>`
3. **底部：✏️ 编辑模式工具栏**（见 assets/edit-mode-sync.html）

## 配图

- 优先 Wikimedia Commons：用 API 搜图 `https://commons.wikimedia.org/w/api.php?action=query&generator=search&gsrsearch=<词>&gsrnamespace=6&gsrlimit=6&prop=imageinfo&iiprop=url&iiurlwidth=1280&format=json`
- **每张图必须 curl 验证 HTTP 200**；图要和地点对得上（曾因图不对返工）
- 官网图（餐厅/品牌）可用但要防盗链失效

## 内容规则

- 英文地名必须配中文注解 + 一句话解释，否则"看不懂没概念"
- 每个点都写停留时长和交通耗时
- **不替老板决定交通方式**——只给对照方案（价格/耗时），等拍板；已拍板的写 ✅，没拍板的写 ⏳
- 待办分级：🔴 急 / 🟡 已定方案 / 🟢 可延后；办完的标 ✅ 并填确认号
- 预订原则类偏好（如有）写在总表上方的醒目 tip 里

## 酒店比价行规范（看房任务必按此做）

- **比价列固定为**：官网 / Booking / 携程 + 一列「👉 建议渠道」，比价表上方 hint 写明汇率口径（如 `1,000 ISK ≈ ¥53`）
- **含早和取消条款必须同口径对比**：官网 "From" 价通常 = 不可退 + 不含早（免费取消常要 +10% 左右）；携程常见"无早 + 代理 + 部分不可取消"。不同口径的低价没有可比性，必须换算成同条款再比
- **Booking 有反爬**，抓不到就标「需点开自查」，不要编价格
- **警惕携程代理库存**：官网售罄但携程显示有房 = 代理房，早餐/取消条款可能与官网完全不同，必须点进详情逐条确认后再建议
- 总表加「实记💰」列：已付款的实际金额填这里，和"预算/报价"分开，方便最后算总账

## 交接存档

同目录维护一份 `<项目>-交接存档.md`：文件清单+链接、已定事实、待办清单、用户偏好、下一步建议。每次改完网页同步更新它——换 agent 接手时靠它零成本续上。
