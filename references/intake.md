# 第 0 步：交互式需求采集（开工前必做）

做攻略最大的翻车不是查错资料，而是**需求没问清就开工**——冰岛项目实战花了约 20 轮对话才收敛需求。用这张清单结构化提问，3 轮内收敛。

## 提问清单（按优先级，缺什么问什么，已说的别重复问）

**① 硬约束（不知道就没法排）**
- 出发地 / 目的地 / 出行日期 / 总天数
- 人数与构成（几间房？情侣/家庭/朋友）
- 已出票的航班、已付款不可退的项目（这些是锚点，行程围着它们排）
- 签证 / 驾照 / 国际学生证等证件状态

**② 预算与住宿偏好**
- 预算档位（经济 / 舒适 / 轻奢 / 不计成本），重点问**机票舱位和酒店单晚预期**
- 酒店 vs 民宿 vs 特色住宿（冰屋/庄园/设计酒店），是否有"必住清单"
- 是否用积分 / 高端卡权益（FHR、酒店会籍）——影响比价渠道

**③ 旅行风格（决定节奏）**
- 打卡出片 vs 深度体验 vs 躺平度假（直接问："每天想排几个点？"）
- 绝不项（例：不早起、不观鲸、不自驾冰雪路）
- 餐饮要求（米其林打卡 / 当地特色 / 随便吃）
- 体力与作息（能否接受 6 小时极光团凌晨回酒店）

**④ 协作方式（决定交付形态）**
- 谁执行预订（本人 / 助理 / 旅行社）→ 决定要不要交接分发和编辑指南
- 需要哪些产物：在线看板 / PDF / 两者都要

## 提问纪律

- **一次最多问 4-5 个**，按上面顺序分批问，别甩一张 20 问的问卷
- 用户回答完，**复述一遍关键约束让用户确认**再开工（"我理解是：4 人 2 间、商务舱预算、南岸多待、不观鲸——对吗？"）
- 用户说"你看着办"的项，给 2-3 个方案附利弊，**不替用户拍板**，拍板后写 ✅ 锁定
- 中途改需求很正常（冰岛项目改过 4 次大方向），改完同步更新看板和存档，不抱怨
